# Hype-or-Not: Upstream Triage Shield & Reality-Check Engine

An autonomous, upstream reality-check shield for developers, AI engineers, and agencies. Filters incoming links, newsletters, GitHub repos, YouTube tutorials, and Telegram/X drop-offs for technical substance, AI slop density, and architectural alignment before they reach testing queues or internal codebases.

---

## The Problem It Solves

AI engineering teams and developers are inundated with:
- **Influencer Engagement-Bait:** *"This one tool replaces 10 developers overnight!"*
- **Vapourware GitHub Repos:** Repositories with high star counts generated by marketing threads, but with empty stubs, failing builds, or unmaintained code.
- **Unedited AI Slop:** Newsletters and technical blogs written entirely by raw LLMs with zero empirical testing or factual verification.
- **Hidden Cost & Token Traps:** "Free" frameworks that secretly require expensive SaaS subscriptions or execute runaway autonomous loops that burn through API credits.

**Hype-or-Not** enforces a strict **Two-Phase Triage Gate** to filter the signal from the noise instantly.

---

## Two-Phase Evaluation Architecture

```
[ Candidate Drop-off / URL / Tool ]
                 │
                 ▼
┌───────────────────────────────────────────────┐
│     PHASE 1: Reality, Slop & Substance        │
│  - Slop Heuristics Audit (burstiness & buzz)  │
│  - Primary Source Grounding (repo/code/docs)  │
│  Is it real technical signal, or empty hype?  │
└───────────────────────┬───────────────────────┘
                        │
             ┌──────────┴──────────┐
             │                     │
    [ EMPTY HYPE / SLOP ]    [ SUBSTANTIVE ]
             │                     │
             ▼                     ▼
        RULE OUT        ┌───────────────────────────────────────────────┐
       (Hard Stop:      │       PHASE 2: Architecture & Policy Gate     │
     save attention     │  - Cost & SaaS Gate (low cost vs. paywall)    │
       and tokens)      │  - Token Economy Gate (no runaway loops)      │
                        │  - Parity & Privacy Gate (local/open data)    │
                        │  Is it architecturally aligned with project?  │
                        └───────────────────────┬───────────────────────┘
                                                │
                                     ┌──────────┴──────────┐
                                     │                     │
                               [ MISALIGNED ]         [ ALIGNED ]
                                     │                     │
                                     ▼                     ▼
                                 RULE OUT          PROMOTE TO QUEUE
                             (Policy Failure)      (or STUDY / DEFER)
```

### The Hard Stop Rule
If a candidate fails Phase 1 (`EMPTY HYPE`), triage terminates immediately with `RULE OUT`. The agent never spends tokens or human attention evaluating architectural fit for marketing fluff.

---

## Features

- **Automated Slop & Burstiness Scoring:** Built-in Python CLI (`scripts/evaluate.py`) that analyzes sentence length variance ($CV = \sigma / \mu$), em-dash frequency, and 20 known AI writing anti-patterns.
- **Universal Storage Adapters (`scripts/append_triage.py`):** Log triage decisions to:
  - Local CSV (default, zero setup)
  - Local Markdown table
  - Local JSON Lines (JSONL)
  - Google Sheets (via Google Workspace CLI `gws`)
- **Parametric Policy Gates (`config.example.yaml`):** Easily configure cost thresholds, allowable open-source licenses, and token loop constraints without modifying agent prompts.
- **Zero Mandatory Third-Party Dependencies:** Written in pure Python standard library.

## Quick Start

### 1. Evaluate Text or a Repository README
Run the standalone evaluator on any text string, clipboard snippet, or README file:

```bash
# Evaluate text directly:
python scripts/evaluate.py --text "In today's fast-paced digital landscape, this revolutionary game-changer seamlessly unlocks AI..."

# Or evaluate a local file:
python scripts/evaluate.py path/to/README.md
```

Sample output:
```text
============================================================
 HYPE-OR-NOT TECHNICAL SUBSTANCE & SLOP AUDIT
============================================================
 Total Words:           30
 Total Sentences:       2 (avg 15.0 words/sentence)
 Burstiness (CV):       0.2 (Monotonous/AI-like)
 Em Dash Count:         0
 Marketing Buzzwords:   7
   Matched terms:       game changer (1), testament to (1), seamlessly (1), delve into (1), in today's fast paced (1), holistic approach (1), cutting edge (1)
 Code Blocks:           0
 Technical Markers:     0
------------------------------------------------------------
 Slop Density Score:    90.0 / 100
 Suggested Verdict:     EMPTY HYPE
============================================================
```

### 2. Log Triage Decisions
Log entries to your preferred destination using `scripts/append_triage.py`:

```bash
# Log to local CSV (creates triage_log.csv automatically):
python scripts/append_triage.py \
  --title "SQLite Vector Search" \
  --url "https://github.com/asg017/sqlite-vec" \
  --verdict "SUBSTANTIVE" \
  --alignment "ALIGNED" \
  --recommendation "PROMOTE TO INTAKE QUEUE [Local Embeddings]" \
  --priority "P1 (High)" \
  --impact "Enables zero-SaaS vector search directly in local SQLite." \
  --summary "Lightweight C/Python vector search extension with MIT license and extensive benchmarks."

# Log to local Markdown table:
python scripts/append_triage.py --backend markdown --output-file ./TRIAGE.md ...

# Log to Google Sheets:
python scripts/append_triage.py --backend gsheet --spreadsheet-id "<YOUR_SPREADSHEET_ID>" ...
```
